# Home Music CD rack

## Rack and Carousel display

Settings -> Display mode switches immediately between **Rack** (initial default) and **Carousel**. Each browser remembers the mode, with separate preferences in Demo. Carousel centres a single cover and its existing playback/volume controls, with up to four unique neighbouring spines per side. Spines remain readable, slightly angled, and retain standard/fatbox proportions. Settings and Now Playing become fixed buttons above the frame. Horizontal swipes/drags, the album arrows and keyboard Left/Right browse circularly; track buttons still change tracks. Browsing never starts playback and does not follow playing-album changes automatically. Now Playing returns to the receiver's current album. Zero/one/two-album catalogues are supported without duplicated neighbours. The volume modal blocks navigation and all underlying controls. Rack behaviour remains unchanged, including double-tap to close its cover; Carousel keeps its focused cover open.

Carousel covers use an authenticated `size=512` artwork variant. The NAS's existing `/usr/bin/convert` resizes without upscaling and caches JPEG thumbnails outside releases in account-scoped catalogue artwork folders; file size/mtime invalidate changed covers. A small in-flight map coalesces concurrent requests. If conversion is unavailable, the original image remains the fallback. The rack retains original-resolution covers. No new runtime package or external CDN is required; navigation is a small circular-layout module using native pointer events and CSS transforms, with reduced-motion support.

Login persistence: app sessions expire after **30 days without browser activity**. HttpOnly/SameSite=Strict cookies persist across browser restarts and are renewed on authenticated requests. A read-only Audio Station player-list check runs after five minutes without successful NAS activity to help keep DSM sessions alive, even when the browser is closed. It never changes playback, volume or queues and does not renew the user's 30-day idle limit. Transient NAS outages preserve the app session; an explicitly invalid/revoked NAS session requires sign-in. Passwords are never saved. Sessions remain in server memory, so deployment, service restart or NAS reboot still requires sign-in. The standalone public Demo build has no NAS service or keepalive.

## Demo and public static build

The connection screen offers **Demo** without NAS sign-in. Demo mode uses 97 locally generated albums and a silent in-browser receiver simulation, including Play/Pause, track changes, Now Playing, volume/mute, sorting and CD size. Some sample albums are multi-disc fatboxes. Demo tracks advance every 30 seconds while playing; no audio is produced. Settings -> Exit Demo returns to the connection screen. No NAS discovery, artwork, catalogue, state, playback or volume requests run while Demo is active. Demo browser preferences are separate from NAS preferences. Demo mode does not change or stop real amplifier playback.

Normal NAS racks now contain real albums only, plus Settings and Now Playing. An empty catalogue shows **No albums found**, with a Refresh Rack hint; both utility spines remain usable.

Run `npm run build:demo` to create a standalone site in `dist/`. Its build-time configuration is Demo-only: the NAS login form is removed and startup does not attempt NAS discovery or session checks. Only an explicit list of browser assets is copied; the NAS server, catalogue, release scripts and SSH material are not included. `vercel.json` selects this build and output folder. Set the Vercel project's Root Directory to `audio-station-test`; no NAS credentials or environment variables are required. Publishing is a separate action. `npm start` and NAS deployment continue to serve the full NAS + Demo app from `public/`.

Compilation fallback: when Audio Station omits album artist, tracks inside `Various Artists/<album>` or matching numbered `<album>, Disc N` / `<album> Disk N` folders use `Various Artists` as the inferred album artist. The source album folder must match the tagged album title. Explicit album artists take priority, track performer tags remain unchanged, and other locations retain the track-artist fallback. Matching sibling disc folders still determine fatbox packaging. Catalogue schema v3 forces older split catalogues to rebuild; saved spine colours remain in their separate files.

Requires Node.js 22 or newer. Run `npm start` for local development at http://localhost:8787. The production prototype runs on the NAS at http://YourNASName.local:8787; see [NAS hosting](nas/README.md) for access and the repeatable PC deployment command.

Sign in using a DSM account allowed to use Audio Station and DLNA renderers. Device selection defaults to a remembered output or Denon DLNA. Later visits with a valid service session open the rack directly. Passwords are never stored, and deployments expire in-memory login sessions. HTTP on the home LAN is the user's current choice; ordinary LAN PWA installation/service-worker features require HTTPS, which is deferred.

The NAS rack contains Settings, Now Playing and the real albums indexed by Audio Station. The 97 fictional sample albums appear only in Demo mode. There is no ElevenLabs synthetic album. Albums are grouped by their embedded album title and album artist (falling back to track artist). Track order is disc number, then track number. Within one tagged album, a fatbox requires sibling track folders with the same base album name and distinct numbered Disc/Disk suffixes (for example Album, Disc 1 and Album, Disc 2). Different album folder names under an artist remain separate standard cases. One disc folder alone, mismatched names/parents or duplicate disc numbers do not qualify. A fatbox has two labelled spine panels and a narrow black centre section. This deliberately simple rule does not model other packaging or distinguish identically tagged editions.

Settings offers Sort by: Artist name (default), Album name, or Album date. Artist/title ordering is A-Z, with natural number ordering and alphabetical tie-breakers. Album dates come from Audio Station tags and sort oldest first; undated albums and synthetic previews follow, ordered by artist/title. All three orders are prepared from the compact summaries when the catalogue is loaded. Selecting a dropdown item alone does not reorder the shelf. The single Refresh Rack button rebuilds the NAS catalogue for additions/deletions and applies the selected order. It stays enabled when the sort choice is unchanged, and disables temporarily while refreshing. This replaces the separate Refresh library action. The applied sort choice is saved per browser. Settings and Now Playing remain first; applying a refresh closes the displayed cover and returns the shelf to its beginning without changing receiver playback. Saved spine styles and synthetic cover artwork stay attached to their albums across sorting.

Real albums get a saved spine colour estimated from their cover artwork. A small canvas samples the dominant colour with extra weight on the edges, which are more likely to be the background. Black or white text is chosen using relative luminance and the higher contrast ratio. Estimation is queued one visible album at a time after rendering, rather than loading the full library's covers at startup. Account-scoped choices are saved on the NAS alongside the catalogue in a separate `-spines.json` file, survive catalogue refresh and app deployment, and are included in later album summaries so other browsers reuse them. Demo sample albums retain their generated colours; missing real artwork retains its fallback palette. No literal spine images are used.

The first catalogue scan reads Audio Station's indexed song metadata. It saves a cache scoped to the NAS account on the NAS, outside app releases. Subsequent rack loads receive only compact album summaries, without tracks or filesystem paths. Track details are returned when an album is opened; its Folder.jpg/cover image is fetched separately and cached privately by the browser. Audio files are never read or streamed through the PWA service. The catalogue expires after 24 hours, or can be rebuilt immediately with Settings -> Refresh Rack after uploading/deleting music. This also clears the browser's track cache. The first-ever scan of a large collection can take longer; later visits reuse the persistent catalogue, including after a service update. The cache holds metadata and song identifiers, never passwords or NAS login sessions.

Covers open over their selected spine; double-tapping the cover or Escape returns it to the rack. Opening a cover never starts playback. Play replaces the receiver queue with the selected album and starts track one; the same button pauses/resumes an existing matching queue. Previous/Next are track controls and start playback even from paused state, including across disc boundaries. Closing the cover leaves playback running. Now Playing identifies the album currently reported by Audio Station and brings its cover into view, without starting music. Demo sample covers have silent simulated playback and volume controls. Real artwork falls back to a generated cover if unavailable.

A compact V button at the right of the transport row opens a native modal volume dialog centred over the artwork. While it is open, the rack, cover and track controls are inert, with additional application guards against album/track commands. X or Escape closes only the volume dialog. The dialog reads the selected renderer's current Audio Station volume on opening, polls while visible, and makes relative one-unit changes by reading fresh receiver state before each command and reading back afterward. It uses RemotePlayer.control action `set_volume`. Following Audio Station's own implementation, Mute sets volume to zero and Unmute restores the previous known level, shared across app sessions for that receiver in service memory. It never invents a restore level after a restart or an externally set zero; + can raise the volume from zero. Volume commands share the receiver lock with playback commands and do not modify playback state or the queue. Unknown/unsupported volume disables controls and shows an inline error. Live Denon verification covered 41 -> 40 -> 41, mute to zero and unmute to 41, blocked underlying album/track taps, and X dismissal while the current track kept playing.

Shelf height adapts to the viewport, with black space above/below. Standard spines retain a 12:1 height-to-width ratio; fatboxes are 2.25 standard widths. Covers remain square. Rack position, CD size and device choice are remembered separately by each browser. Errors appear in dialogs. No playback progress bar is implemented.

All browser API calls go to the same-origin Node service. It validates Host/Origin and holds authentication in HttpOnly cookies plus in-memory NAS sessions. Audio Station controls the renderer directly, leaving the NAS/receiver responsible for advancing the album queue. Changes from other browser controllers appear when a playable cover is open and status is polled. Shared-device mutation locks prevent overlapping commands; sequential commands from two controllers can still override one another.

On the NAS, `NAS_LOCAL=true` discovers the NAS using its current interface addresses. `BIND_ADDRESS=::` listens on IPv4 and IPv6. `MUSIC_ROOT` optionally overrides `/volume1/music` for artwork reads; only artwork underneath the real music root and in an authenticated catalogue album's folder is served. Account-scoped catalogue files are stored under `$HOME/home-music/catalogue`; `CATALOGUE_DIR` can override that location. Local PC development uses the NAS SMB music share for artwork unless MUSIC_ROOT is configured.

Run `node --test` before deployment. Tests cover access checks, artist/album grouping, multi-folder fatbox classification, disc/track order, cache refresh, Now Playing identification, queue replacement, and playback boundaries. Audio Station's internal APIs are discovered at login and may vary by package version. No library tags or audio files are modified by this app.
